# 8086读写总线周期对比

Q：8086CPU最小模式的读总线周期和写总线周期相比，T2状态下AD15~AD0呈高阻态的原因？

A：这是 8086 地址/数据复用总线**方向切换**的必然要求。

## 核心原因

**AD15~AD0 是分时复用总线**。在 T1 状态它输出地址，而在读周期中后续要改为**输入数据**。CPU 必须在 T2 状态将其置为高阻态（浮空），**把总线控制权释放给外部设备**（存储器或 I/O 接口），外部设备才能将数据送上总线，供 CPU 在 T3 状态采样。

## 读/写周期对比

| 状态 | 读总线周期 | 写总线周期 |
|------|-----------|-----------|
| **T1** | AD15~AD0 输出地址，ALE 锁存 | AD15~AD0 输出地址，ALE 锁存 |
| **T2** | **AD15~AD0 高阻态**（浮空），A19/S6~A16/S3 输出状态 | **AD15~AD0 输出数据**（CPU 驱动），A19/S6~A16/S3 输出状态 |
| **T3** | 外部设备驱动数据到 AD 总线，CPU 采样 | CPU 保持数据，外部设备写入 |
| **T4** | 总线周期结束 | 总线周期结束 |

## 为什么写周期不需要高阻态？

写周期中 CPU 始终是**发送方**。T1 输出地址后，T2 直接切换为输出数据即可，总线方向没有改变（都是输出），因此无需浮空。

## 一句话总结

> **读周期需要"让出"总线给外部设备驱动数据，所以 T2 必须浮空；写周期 CPU 自己驱动数据，所以 T2 直接输出。**
