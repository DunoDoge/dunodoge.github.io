# PL/SQL 中的游标是什么？

## 一、核心本质：游标是"结果集遍历器"

游标本质上是一个**指向查询结果集的指针/句柄**，它架起了"集合操作"与"逐行处理"之间的桥梁。

---

## 二、逐句拆解

### 1. "游标将一个命名缓冲区和一个查询语句绑定在一起"

- **命名缓冲区**：游标在内存中开辟一块区域，用于存放查询结果集的元数据（列结构、数据类型等）和当前行数据。
- **绑定查询语句**：游标在声明（DECLARE）时必须与一个 `SELECT` 语句绑定，定义好"要查什么"。
- 这一步只是**定义**，还没有真正执行查询。

```plsql
-- Oracle PL/SQL 示例
CURSOR emp_cursor IS
    SELECT empno, ename, sal FROM emp WHERE deptno = 10;
-- emp_cursor 就是"命名缓冲区"，绑定了后面的 SELECT 语句
```

---

### 2. "查询执行后的结果集数据通过游标把面向集合的操作转换成面向元组的操作"

这是游标最核心的作用：

| 维度 | 集合操作（SQL） | 元组操作（游标） |
|------|----------------|------------------|
| 处理单位 | 整个结果集（集合） | 单条记录（元组/行） |
| 典型语句 | `SELECT`、`UPDATE`、`DELETE` | `FETCH` |
| 执行方式 | 一次性完成 | 逐行、顺序遍历 |
| 控制能力 | 无（自动完成） | 有（可控制每行的处理逻辑） |

**为什么需要这种转换？**
- SQL 是**声明式语言**，只描述"要什么"，不描述"怎么逐行处理"。
- PL/SQL（或 C/Java 等过程语言）是**过程式语言**，需要逐行控制业务逻辑。
- 游标让过程语言能够**一行一行地"消费"** SQL 返回的集合数据。

---

### 3. "用 PL/SQL 语句逐一从游标中获取记录，并赋给主变量"

- **FETCH**：从游标中读取当前行，并将列值赋给程序变量（主变量）。
- 每 FETCH 一次，游标指针自动下移一行。

```plsql
OPEN emp_cursor;          -- 执行查询，结果集载入游标
LOOP
    FETCH emp_cursor INTO v_empno, v_ename, v_sal;  -- 逐行获取
    EXIT WHEN emp_cursor%NOTFOUND;                    -- 没有数据则退出
    -- 对 v_empno, v_ename, v_sal 进行业务处理
END LOOP;
CLOSE emp_cursor;         -- 释放资源
```

---

### 4. "交给过程语言进一步处理每个元组"

- 获取到主变量后，就可以用 PL/SQL 的**过程化逻辑**进行复杂处理：
  - 条件判断（`IF ... THEN`）
  - 循环控制
  - 调用其他过程/函数
  - 逐行提交或回滚
  - 与其他非数据库操作交互

---

## 三、类比理解

| 类比 | 解释 |
|------|------|
| **水龙头** | SQL 查询像打开水龙头，水（数据）一次性流出；游标像用杯子**一杯一杯接水**，每杯单独处理。 |
| **磁带播放器** | 查询结果是整盘磁带，游标是播放头，可以**逐首播放**（FETCH），也可以快进、暂停。 |
| **快递分拣** | SQL 查询生成一整车包裹（集合），游标是**逐个取出包裹**交给工人（过程语言）处理。 |

---

## 四、游标的工作生命周期

```
DECLARE（声明/绑定查询） 
    → OPEN（执行查询，生成结果集，指针指向第一行前） 
    → FETCH（读取当前行，指针下移） 
    → ...重复 FETCH... 
    → CLOSE（关闭游标，释放资源）
```

---

## 五、总结一句话

> **游标 = SQL 的集合结果 + 过程语言的逐行控制能力**

它解决了"SQL 只能整体返回数据，而过程语言需要逐行处理数据"之间的矛盾，是数据库**过程化扩展**（如 PL/SQL、T-SQL）中不可或缺的机制。
